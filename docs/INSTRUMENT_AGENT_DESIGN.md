# Agent 辅助仪器测量：技术选型与开发方案

> 目标：从“只读真值填表”升级为**真实仪器读数**（千分尺/卡尺/直尺），由程序做确定性操作与判读，
> agent 只在视觉定位/异常时介入。本文回答“怎么开发、选什么技术栈”，并给出可落地的分层与状态机。

## 1. 结论（选型）

| 层 | 选型 | 理由 |
|---|---|---|
| UI 操作 | 现有 `input.exe` / `input2.exe`（SendInput，DPI 感知） | 已验证；短按 hold 可模拟棘轮；无需引入宏录制器 |
| 状态/读数 | 现有 UIA（`ValuePattern` / `ValueText` / `ValueText2` / `MessageText`） | 千分尺数字读数、卡尺读数、提示都直接可读；零依赖 |
| 视觉感知 | **Python + numpy + Pillow**（已安装） | 模板匹配、边缘/刻度检测足够；不引入 OpenCV 的 40MB 依赖 |
| 可选视觉 | `opencv-python-headless`（Apache-2.0） | 仅当模板匹配/直线检测不够稳时再加；不是首选 |
| Agent 兜底 | `image-recognizer`（MiMo V2.5）读截图返回坐标 | 解决“锁钮/钳口/落点”这类视觉定位；**只在失败时调用**，并缓存 |
| OCR | 不用 | 数字由 UIA 读；直尺是图形刻度，像素法比 OCR 更准 |
| 宏录制/按键精灵/SikuliX | 不用 | 坐标/图像驱动、不可版本化、脆弱；与声明式状态机冲突 |
| ML 检测（YOLO 等） | 不用 | 无训练数据、过重；模板匹配 + 几何先验足够 |

**一句话**：核心仍是 `Python + UIA + SendInput`；视觉用 `numpy/Pillow` 做确定性判读；
agent 只做“看图给坐标”的兜底；所有读数必须来自仪器 UIA/像素，而不是内存真值。

## 2. 分层架构

```
measure_instrument.py      # 状态机（setup/prepare/place/close/read/reset × 6）
  ├─ instruments.py        # 每台仪器的动作与判据（千分尺/卡尺/直尺）
  ├─ perceive.py           # numpy+Pillow：模板匹配、区域差分、刻度/边缘
  ├─ agent_bridge.py       # needs_agent.json / agent_hints.json（图像坐标→屏幕坐标）
  └─ core/controller.py    # 现有窗口/输入/UIA/截图
```

### 2.1 每台仪器的确定性部分

- **千分尺（薄板厚/纸厚）**：右键解锁 → 短按张开 → 拖物体入隙 → 短按闭合到读数平台 →
  `ValueText2` 读数（内嵌 QFC **无零偏**，不减 0.02）→ btnOut。
- **卡尺（薄板宽）**：右键锁钮解锁 → 拖 `DragRect` 到略小于物体（值≈37.9mm）→
  拖物体进外量爪 `OuterCanvas` → `ValueText` 读数 → btnOut。
- **直尺（薄板长/孔径、纸长/宽）**：拖物体到尺带 → 放大镜/像素法读左右缘 →
  `measure_ruler_pixels.py`（主刻度间距≈38.8px/cm）→ btnOut。

### 2.2 判据（每步都要可验证）

| 步骤 | 判据 |
|---|---|
| 解锁 | `MessageText` 出现“已解锁”/锁图标状态；拖 `DragRect` 后值变化 |
| 张开 | `ValueText/ValueText2` 达到目标开口（±2mm） |
| 放入 | `MessageText` 不含“放不进去”；物体模板从盒内消失/出现在钳口区域；读数变化 |
| 闭合 | 连续 3 次采样值不变（平台）；且不低于物体真值附近 |
| 读数 | UIA 值稳定 3 次；可选：截图刻度目视/像素复核 |
| 复位 | `btnOut` 后仪器/物体消失，盒内物体重新出现 |

### 2.3 Agent 兜底契约

程序失败时写 `logs/needs_agent.json`：

```json
{
  "task": "MeasureGBB",
  "step": "place",
  "screenshot": "data/.../shots/caliper_before_place.png",
  "image_size": [1406, 1096],
  "window_origin": [1900, 1000],
  "question": "给出外量爪开口中心/待测板中心的图像像素坐标",
  "candidates": ["outer_jaw_gap", "plate_box"],
  "tried": [[515,280],[520,300],[520,360]]
}
```

agent 返回图像像素坐标（不是屏幕坐标）：

```json
{"outer_jaw_gap":[526,275],"plate_box":[145,635],"confidence":"high","notes":"..."}
```

程序把图像坐标 + 窗口原点映射成屏幕坐标；同一布局/视图的答案写入 `logs/agent_hints.json` 缓存，
后续 6 次重复不再调用 agent。

## 3. 为什么 agent 只做“兜底”而不是每步调用

- 6 次 × 7 量 = 42 个循环；每步调用 agent 会产生 42+ 次截图/模型调用，慢且贵。
- 锁钮/拖动面/钳口在**同一会话同一视图**内位置固定，一次定位可缓存。
- 数值判读用 UIA/像素，agent 不参与算数，避免“模型读错刻度”污染数据。

## 4. 开发路线（建议顺序）

1. **卡尺 B（最难的放置）**：先做 `place` 的候选点搜索 + 模板匹配验证；失败时 agent 给落点。
2. **千分尺 H（薄板/纸）**：锁/短按/闭合平台成熟，先跑通 6× 读数，验证 `ValueText2` 与真值偏差。
3. **直尺 L/D（薄板）**：像素刻度 + 物体边缘检测；边缘不确定时 agent 看局部放大图。
4. **纸 L/B**：直尺同法。
5. 把 42 个真实读数接入 `build_fill_plan.py`，走现有填表/verify/submit 链路，`data_source: real_instrument`。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 放置命中区与视觉钳口不一致（已知坑） | 候选点网格 + 模板匹配 + agent 兜底；记录每次失败截图 |
| `MessageText` 残留旧提示 | 不做唯一判据；结合值变化/模板/截图 |
| 卡尺锁钮/拖动面位置随视图偏移 | 每次视图打开后重新用 BAML 公式/agent 定位，缓存到该视图 |
| 直尺放大镜不跟随合成鼠标 | 像素刻度法（已实现 `measure_ruler_pixels.py`）；放大镜只作目视辅助 |
| 真实读数与真值有偏差 | 6× 读数取平均；记录偏差%；超容差时重测或报告 |
| 合规 | 真实 UI 操作；不写内存；`data_source: real_instrument`；保留截图/UIA 证据 |

## 6. 本次实测结果（2026-11-18 测试账号会话）

### 6.1 千分尺（薄板厚度）——已跑通真实读数

- 视图/窗口：`带孔薄板` @ (1900,1000)，PID 26744；模式「厚度测量」+ 千分尺。
- **锁钮命中区不是视觉圆心**：视觉圆心 (680,495) 右键无效；用“指针方向”像素判据扫描，
  命中区在视图 **(672,475)**（指针朝下=锁、朝右=松）。脚本：`probe_mic_knob.py`。
- 初始开口 3.321mm；把盒内薄板从 (147,672) 拖到测砧/螺杆间隙 (440,467)，盒变空。
- 用 `input2.exe hold 2912 1467 600 1` 短按闭合 21 次，读数在 **2.011mm** 形成平台
  （继续短按 3 次仍不变）——物体已夹紧。
- 会话真值 2.005mm，读数偏差 **+0.006mm = +0.30%**（放置抖动；内嵌 QFC 无零偏，不要减 0.02）。
- 证据：`data/round_2026-11-18m_instr/instrument_probe.json`、
  `tools/framework/logs/mic_knob_probe.png`、`mic_closed.png`。

**结论：千分尺是当前最适合“Agent 辅助真实测量”的仪器**——锁钮/短按/读数都能程序化，
agent/像素判据只用于一次性的锁钮定位。

### 6.2 卡尺（薄板宽度）——部分打通

- 锁钮：右键视图 (550,335) 可靠解锁（`MessageText` → 已解锁）。
- 拖动：`DragRect` 中心 = 645 + value×3.86 px（value 为 mm）；值 0→45.058→37.031 实测可控。
- **放置仍未成功**：下方区域（y 520..600）是 InnerCanvas，物体 38.08 > 开口 → 提示
  “物体放不进去”，且物体留在场景（盒空，不是回到盒里）；上方视觉钳口区域不是 OuterCanvas 命中区。
- 识图代理能准确给出锁钮 (557,337)、盒内板 (146,672)，但“外爪开口”是基于闭口截图的视觉中心，
  **不能直接当逻辑命中区**。
- 下一步：用“画布命中图”法——对候选点做投放，检测 `ValueText` 是否变成物体值（接受）/
  物体是否留场景（拒绝），建立 OuterCanvas 的屏幕矩形；或从 BAML 的 canvas 变换反算并现场标定。

### 6.3 直尺（薄板长度）

- 物体拖到尺带已成功（盒空、板在尺上）；可用 `measure_ruler_pixels.py` 读主刻度间距（≈38.8px/cm）
  与板左右缘，得到真实长度。放大镜只作目视辅助。

## 7. 选型落地结论

- **核心**：Python + UIA + SendInput（现有框架）足够；不需要 pywinauto/FlaUI/宏录制器。
- **感知**：`numpy + Pillow` 已验证够用（指针方向判别、盒内物体消失、刻度/边缘像素）；
  OpenCV 仅在需要模板匹配/直线检测时再加，不是首选项。
- **Agent**：适合“一次性视觉定位”（锁钮、盒内物体、钳口候选），不适合每步调用；
  逻辑命中区（OuterCanvas）仍需程序探测/几何反算，视觉中心不可直接替代。
- **测量状态机**：每步 action + 判据（UIA 值/指针方向/盒空/Plateau）是正确方向；
  6× 循环用 `btnOut` 复位、重新点仪器，读数带放置抖动，取平均更接近真值。
